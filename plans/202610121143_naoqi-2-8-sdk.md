# NAOqi 2.8: build our C++ against the suite's own 2.8.7.4 SDK

**Status:** Done

Implements [container.md](../specs/container/container.md), "Build files: the C++ SDK" and "The relay's build", as updated on Oct 12, 2026: the 2.8 images compile our C++ NAOqi modules (the native relay today; the C++ fronts the speech work adds next) against `naoqi-sdk-2.8.7.4-linux64.tar.gz` from `aldebaran/nao6-doc-sdk`, the suite's own release, as 2.1 does with its SDK. The 2.8.5.10 SDK, our libqi fork and boost 1.64 are dropped. Left out: 2.1, whose SDK stays on Aldebaran's download server (no copy on GitHub), and the speech work itself, which builds on this one.

Why: the libqi fork headers differ from the real 2.8.7.4 headers in 57 files. Header templates compiled into our modules (`ALProxy::call<T>`, `qi::AnyObject::call<T>`) then disagree with the suite's libraries: values arrive "Invalid" and a Python qi service crashes `naoqi-service` (measured while building a C++ front for `ALTextToSpeech`, `spike/RESULTS.md`). The relay passed only by its narrow use of `ALValue`.
