# The webcam source

**Status:** Done

Implements the `webcam` source of [video-input.md](../specs/host/video-input.md) ("Sources", "The webcam source"), with what it changes in [config.md](../specs/runtime/config.md) ("Sources not built yet", "Example files"), [api.md](../specs/runtime/api.md) ("Lifecycle", step 1 and 6) and [project.md](../specs/project.md) (the `webcam` extra). A host webcam feeds either head camera through OpenCV: centre-cropped to 4:3, scaled to VGA, captured on its own thread with the newest frame served at the camera's `fps`, checked at start and retried when it stops delivering. It leaves out a crop to the NAO's field of view (an `hfov` field), camera names, and an indicator in the sim window (open questions 3, 6 and 7 of the spec); and it has no live test (CI has no webcam): a manual run of `examples/configs/webcam.json` checks it.

## Scope

- `pyproject.toml` — the `webcam` extra (`opencv-python-headless`), taken by the `dev` group; `uv.lock` follows
- `src/naoqi_sim/webcam.py` — new: `to_vga` (crop, scale, BGR to RGB), `check_webcam` (the step 1 check), `Webcam` (a capture thread per device, a `FrameSource` serving the newest frame, retry, indicator logs)
- `src/naoqi_sim/video_input.py` — `NoFrame`: a source with nothing to serve for a slot, which skips it (counted as missed, never logged)
- `src/naoqi_sim/sim.py` — the webcam check at step 1 (no more `DeviceNotBuiltError` for `webcam`), one `Webcam` per distinct device started before the video input and stopped after it, the video input started for any fed camera
- `examples/configs/webcam.json` — new: the webcam on the top camera, the render on the bottom one, the window showing both cameras (`viewer.cameras_display`)
- `pyproject.toml`, `src/naoqi_sim/config.py`, `src/naoqi_sim/viewer.py` — naoqi-viewer pinned at `8f3976f` (its camera display), `viewer.cameras_display` (refused with `headless`) passed through to `NaoqiViewerConfig`; `tests/test_config.py`, `tests/test_viewer.py` pin both (added Oct 16 at review: the example shows what NAOqi serves)
- `README.md` — the `webcam` extra and the example
- `AGENTS.md` — `webcam.py` in the project map
- `tests/test_webcam.py` — new: the conversion, the check's errors, the capture's newest frame, sharing, retry and recovery logs, stop, against a fake capture
- `tests/test_video_input.py` — `NoFrame` skips a slot and counts it
- `tests/test_sim.py` — the webcam check fails before anything starts, the webcam feeds a headless config with no viewer and is released after the video input stops, two cameras on one device share one capture
- specs (`video-input.md`, `config.md`, `api.md`, `project.md`, `viewer.md`: `Updated` until this plan is `Done`), `devices.md`, `_overview.md`, `specs/_index.md`

## Steps

1. Specs updated (this change): the design above, the four specs at `Updated`.
2. `pyproject.toml`: `webcam = ["opencv-python-headless"]`, `dev` takes `naoqi-sim[viewer,webcam]`; `uv lock`.
3. `video_input.py`: `class NoFrame(Exception)`; in `_render`, a source raising it skips the camera's slot like a failed render but counts it in `missed_by_camera` and logs nothing.
4. `webcam.py`:
   - `to_vga(bgr)`: centre crop to 4:3 by slicing, `cv2.resize(..., (640, 480), interpolation=cv2.INTER_AREA)`, `cv2.cvtColor(..., COLOR_BGR2RGB)`; `cv2` imported inside.
   - `open_capture(device)`: the default opener, `cv2.VideoCapture(device)`; the seam tests replace.
   - `check_webcam(device, key, open_capture=None)`: `MissingExtraError` naming `naoqi-sim[webcam]` without `cv2`; `DeviceUnavailableError` naming `key` and the device, with the macOS permission hint on Darwin, when the capture does not open or gives no frame; released either way.
   - `Webcam(device, open_capture=None, retry_s=5, frame_timeout_s=5)`: `name = "webcam"`; `start()` runs the capture thread, `stop()` ends it and releases (idempotent, joining with a timeout so a blocked `read` is left behind as a daemon thread); the thread opens, logs `webcam N is live: WxH (BACKEND)`, reads into the newest raw frame with its time, and on a failed open or read logs one error with the hint, releases and retries every `retry_s` (a recovery logged at info), and logs `webcam N is off` when it stops capturing; `frame()` converts the newest raw frame with `to_vga` (cached per raw frame) and raises `NoFrame` when none came in the last `frame_timeout_s`.
5. `sim.py`: in `_check`, the built-sources check stops refusing `webcam`, and `check_webcam` runs for each distinct webcam device; `_start_video_input` builds a `RenderSource` per rendered camera and one started `Webcam` per distinct device (its stop registered before the video input's, so the teardown stops the video input first), and runs whenever a camera is fed; the world only for a rendered camera.
6. `examples/configs/webcam.json`, the README's install and run lines, the project map; naoqi-viewer's pin moved to `8f3976f` and `viewer.cameras_display` through the config to `viewer_config`.
7. Tests (below), then a manual run of `webcam.json` on macOS.

## Verification

- `tests/test_webcam.py`: a 16:9 and a 4:3 and a tall frame come out 640×480 RGB from their centres (a coloured border cropped, BGR channels swapped); the check raises `MissingExtraError` without `cv2` and `DeviceUnavailableError` with the device and the hint for a capture that does not open or gives no frame, releasing it; a running `Webcam` serves the newest frame, raises `NoFrame` before the first frame and after `frame_timeout_s` without one, retries a failed open and logs the failure once and the recovery once, logs live and off, and releases the capture on `stop()`.
- `tests/test_video_input.py`: a source raising `NoFrame` gets no frame injected and its slots counted, and the other camera carries on.
- `tests/test_sim.py`: a webcam that cannot open fails `start()` before anything starts; a headless webcam config launches no viewer, publishes `webcam`, injects frames and releases the capture after the video input's keys go back to `none`; two cameras on device 0 open it once.
- `uv run ruff check .`, `uv run ruff format .`, `uv run pyright`, `uv run pytest`; the PR's CI.
- Manual: `uv run naoqi-sim run --config examples/configs/webcam.json`, a QVGA subscriber of `CameraTop` seeing the room, `naoqi-sim status` showing `mixed`, the window's camera pictures showing the webcam (top) and the render (bottom).
