# CI workflow

**Status:** In progress

Implements [specs/testing/ci.md](../specs/testing/ci.md): the GitHub Actions workflow (`check`, `fast-tier`, the `e2e-sim` matrix over 2.1 and 2.8 with its image cache), the live tier's `NAO_SIM_E2E_VERSION` switch from skipping to failing, and the Python 2.7 check as a live test. It leaves out the headless viewer and the render camera (milestone 4), which the spec adds to the live entries once they are built.

## Scope

- `.github/workflows/ci.yml` — new: the three jobs, the cache steps, the expected-skip-free live run under `xvfb-run`
- `tests-e2e/support.py` — `NAO_SIM_E2E_VERSION`: the versions the tier runs, and `unavailable()`, which fails instead of skipping when a version is required
- `tests-e2e/conftest.py` — the `nao` fixture's params come from `support.e2e_versions()`
- `tests-e2e/test_modules_live.py` — the Python 2.7 compile check of the image's modules
- `specs/testing/ci.md` — `Draft` → `Stable` (this change), → `Implemented` once the first runs are green
- `specs/testing/testing.md` — open questions 1 and 2 point to what is now built
- `specs/_index.md`, `specs/_overview.md` — CI's status
- `AGENTS.md` — `.github/` in the project map

## Steps

1. `support.py`: read `NAO_SIM_E2E_VERSION` once. `e2e_versions()` returns `[that version]` when set (raising `pytest.UsageError` for an unknown one) and `sorted(VERSIONS)` otherwise. `unavailable(reason)` calls `pytest.fail` when a version is required and `pytest.skip` otherwise; `require_docker` and `ensure_images` use it for their skips.
2. `conftest.py`: `params=e2e_versions()`.
3. `test_modules_live.py`: `test_the_modules_are_python_2_7`, which runs `docker run --rm --entrypoint sh <image> -c "python2 -m compileall -q /opt/naoqi/modules"` on the fixture's image and asserts a zero exit, with the output as the message.
4. `ci.yml`, following nao-viewer's workflow for the actions' versions (`actions/checkout@v7`, `astral-sh/setup-uv@v7`, `actions/cache/{restore,save}@v6`):
   - `check` and `fast-tier` as in the spec's table.
   - `e2e-sim`: free the disk, `uv sync --locked`, compute the key with `uv run python -c` over `docker_images.nao_sim_version()`, `docker_images.recipes_digest()` and `hashFiles('src/nao_sim/suite.py')`; restore `$RUNNER_TEMP/images.tar` and `docker/vendor/images.json`; load and delete on a hit; build, save and cache on a miss; install the GL and Xvfb packages; run the tier with `NAO_SIM_E2E_VERSION=${{ matrix.version }}` under `xvfb-run -a`; on failure, the containers' logs.
5. Specs and indexes as listed in Scope; `AGENTS.md`'s map gets a `.github/` row.

## Verification

- Locally: `uv run ruff check .`, `uv run ruff format --check src tests tests-e2e docker/tts`, `uv run pyright`, `uv run pytest`.
- Locally, the live tier: `uv run pytest tests-e2e -rs` (both versions, skips as before), then `NAO_SIM_E2E_VERSION=2.1 uv run pytest tests-e2e -rs` (2.1 only), and `NAO_SIM_E2E_VERSION=3.0` fails at collection.
- The fast tier on Linux x86_64 in a container (`--platform linux/amd64`, `uv sync --locked`, `uv run pytest`), as the `fast-tier` job runs it.
- The workflow itself is verified only on GitHub: the first runs must show all four jobs green, a cache miss then a hit on each live entry (the hit skipping the build, which proves the image IDs survive `docker save`/`docker load`), and no skip but the spec's expected one. Mark this plan `Done` and `ci.md` `Implemented` then, filling the spec's open questions 1 and 2 with the measured sizes and times.
